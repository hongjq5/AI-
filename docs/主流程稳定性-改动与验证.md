# 主流程稳定性：改动与验证

本文是 2026-10-01 第一阶段开发环境的历史记录，保留当时的实现取舍与复验方法。该阶段保留原有接口、数据库结构和页面布局，修复登录、Excel 上传、图表生成和异步失败处理；当时后端 76 个、前端 32 个回归用例及前后端构建通过。这些数量不是发布清理时重新执行的结果。

## 已修复的行为

- 登录页不再因挂载或重渲染请求图表列表；当前用户保存实际 `data`，登录失效跳转保留原页面地址。
- 两个上传页面统一为 Excel 手动上传，文件必填、仅接受非空 XLS/XLSX、最大 1 MB；提交所选原始文件，使用提交锁防止请求重入，并在结束后恢复按钮状态。同步页面确认图表 JSON 可解析后才显示成功。
- 请求层显式校验后端的 `code/data/message` 响应，业务失败正确拒绝；在页面自行处理错误时避免重复弹出提示。管理员权限读取真实的 `userRole` 字段。
- 三个生成接口统一接受非空、最大 1 MB 的 XLS/XLSX，扩展名大小写均可。
- Excel 解析按真实文件内容识别格式；无效文件、空表或仅表头返回参数错误。保留空单元格的位置，正确转义 CSV 中的逗号、引号和换行。
- 同步成功生成的图表明确保存为 `succeed`，避免已有结果仍显示“等待”。
- 线程池异步任务的排队拒绝、AI 调用异常、返回内容格式错误、状态更新失败都有对应失败处理；队列满返回业务码 `42900`。
- AI 图表配置必须是严格的 JSON 对象，禁止把 null、数组、JavaScript 对象字面量或尾随垃圾保存为成功结果。三种生成方式共用解析器。
- 消息发送时抛异常会尝试将图表标为失败；消费者成功时确认，业务失败时拒绝，每次调用只结算一次消息。确认/拒绝本身的连接异常交由监听容器处理。
- `execMessage` 保存可理解的失败原因；详细异常写后端日志，不把数据库或供应商连接信息直接展示给用户。

## 验证边界

本次测试隔离了 MySQL、Redis、RabbitMQ 和 AI 调用，验证的是程序逻辑及失败路径。原有测试中存在真实数据库写入、消息发送、云存储和 AI 调用；这些外部集成示例未执行，也没有创建真实账户、修改数据库或调用收费 AI。

这次没有增加重试、定时恢复、消息发送确认、幂等锁或事务发件箱。数据库不可用时，失败状态本身也可能写不进去，此时日志会明确记录；进程在任务中途退出也仍需后续恢复机制。不能把本次修复等同于断电、重启或网络中断下的完整任务可靠性保证。

本文仅描述当时的开发与验证过程，不包含个人工作区备份或 Git 发布操作。
