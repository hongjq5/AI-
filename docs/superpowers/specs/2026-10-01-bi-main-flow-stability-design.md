# 智能 BI 主流程稳定性设计

## 背景与目标

当前项目已经具备登录、Excel 上传、AI 图表生成和“我的图表”查询能力，但主流程存在几类会直接影响使用的缺陷：登录页挂载后会发起无关的图表请求，前端提示的上传格式与同步接口校验不一致，线程池异步任务可能因队列拒绝或运行时异常停留在等待/运行状态，失败原因没有真正写入数据库。

本阶段的目标是在保留现有 HTTP API、数据库表结构和页面路由的前提下，让一次图表生成任务具有明确、可追踪、可恢复的状态，并让前端提示与后端约束一致。

## 方案选择

采用定点修复方案。它覆盖已确认的故障点，改动集中在现有控制器、状态定义、登录页和上传表单，避免本阶段引入新的任务服务层或改变消息队列协议。

## 设计

### 后端状态与提交

- 新增图表状态枚举，统一 `wait`、`running`、`succeed`、`failed` 的持久化值；现有数据库字段继续使用字符串，接口响应格式不变。
- 抽取重复的文件后缀校验规则，明确支持 `.xlsx` 和 `.xls`；前端上传组件同步限制为这两种格式，并显示大小限制。
- 线程池异步接口提交任务时捕获 `RejectedExecutionException`。任务记录仍保留，但立即写成 `failed` 并记录“任务队列已满”，接口返回业务错误，避免生成一个永远等待的任务。
- 异步任务体捕获 AI 调用、解析和数据库更新异常，统一调用失败处理方法；失败处理方法写入真实的异常消息，而不是固定占位文本。对外只返回安全的业务信息，详细异常记录日志。
- RabbitMQ 消费者沿用同一状态枚举和失败处理约定，修复其失败信息写入，保持确认/拒绝消息行为不变。

### 前端主流程

- 删除登录页挂载时对图表列表接口的调试请求及控制台输出，登录页只负责登录和获取当前用户。
- 上传表单使用 `accept` 限制 Excel 文件，提交前校验文件存在；同步和异步页面的提示统一为 Excel 文件，避免用户上传 CSV 后才收到后端错误。
- 保留现有“我的图表”轮询之外的页面结构和接口调用方式；当后端返回失败状态时直接展示 `execMessage`。

### 错误边界与兼容性

- 不修改现有接口路径、请求参数名、响应包装类和 `chart` 表字段。
- 对历史数据中的状态字符串继续兼容；枚举只作为新代码的唯一来源。
- 线程池拒绝、AI 异常、结果解析失败、状态更新失败都必须落到 `failed` 状态；如果失败状态本身无法更新，记录错误日志并保留原异常。

## 测试策略

- 后端单元测试覆盖状态值、文件扩展名校验、任务提交被拒绝时的失败落库、异步异常的失败落库，以及失败信息使用真实消息。
- 对 RabbitMQ 消费者的失败路径增加不依赖外部 RabbitMQ 的单元测试；已有集成性质测试不作为本阶段唯一验证手段。
- 前端运行 TypeScript 检查和 ESLint；对登录页使用静态检查确保不再调用图表列表接口，对上传表单检查 `accept` 和必填文件校验。
- 使用 Maven 测试验证后端编译与测试；如果当前环境缺少 Node 依赖，则保留代码并明确记录前端验证缺口。

## 验收标准

1. 打开登录页不会请求图表列表接口，也不会输出调试日志。
2. 同步、线程池异步和消息队列异步三条生成路径对 Excel 扩展名和状态值的约束一致。
3. 线程池满、AI 调用抛异常、AI 返回格式错误时，图表最终状态为 `failed` 且 `execMessage` 包含对应原因。
4. 正常成功任务仍然保存图表结果，现有“我的图表”页面可以继续展示。
5. 后端测试通过；前端 TypeScript/ESLint 在依赖可用时通过，无法运行时说明具体原因。
